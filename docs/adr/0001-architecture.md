# ADR-0001 — Архитектура движка KB (greenfield, Go, TDD+DDD+CA)

- Статус: accepted
- Дата: 2026-06-24

## Контекст

Существующий тулинг KB — ~2650 строк процедурного Python (`knowledge-base/_tools/`)
и частичная копия в `kb-engine/` (Python, ~1270 строк), без тестов, со смешением
логики, I/O и генерации HTML. Цель: публичный движок senior-grade, который смотрит
сторонний разработчик; работает с любой KB, не содержит личных данных.

## Решение

Пишем движок **с нуля на Go** (greenfield), по **TDD + DDD + Clean Architecture**.
Не рефакторим Python — переписываем, используя старый код как спецификацию.

### Язык
Go 1.26. Причина: целевой язык владельца, сильнее как публичный артефакт (Go senior),
строгая типизация хорошо ложится на DDD-инварианты.

### Слои (Clean Architecture, зависимости внутрь)
- `internal/domain` — Entities/Value Objects с инвариантами. Без I/O, без зависимостей
  на инфраструктуру. Доменные ошибки `var ErrXxx`.
- `internal/usecase` — сценарии (аудиты, стюардшип, сборка отчётов). Здесь объявляются
  интерфейсы репозиториев (DIP: интерфейс у потребителя, не в domain).
- `internal/adapter` — реализации: чтение/запись JSON-каталога, рендер отчётов.
- `cmd/kbengine` — CLI: парсинг флагов → usecase → вывод. Без бизнес-логики.

### Дисциплина (механические гейты)
- **TDD**: два коммита на поведение — `test(...)` (RED) → `feat(...)` (GREEN). Один
  `feat:` с тестами вместе = нарушение.
- **DDD**: Entity/VO только через `NewXxx(...) (*X, error)` с валидацией инвариантов;
  прямое `domain.X{...}` вне `domain/` запрещено; бизнес-инварианты живут в domain.
- **CA**: handler/CLI не содержит бизнес-логики; repository-интерфейсы в usecase;
  без cross-module связей мимо границ.
- **Verification**: перед claim «senior-grade» — внешнее ревью (code-reviewer),
  каждая ось (TDD/DDD/CA) ≥8/10. Самосертификация запрещена.

### Данные
Движок data-agnostic: путь к KB через флаг (`--kb-home`). Личная KB владельца НЕ
коммитится. Тест-данные — синтетические фикстуры в `testdata/`.

## Последствия
- Полный рерайт дольше рефактора, но даёт честный TDD (test-first) и чистую базу.
- Старый Python-тулинг остаётся в работе, пока Go-движок не достигнет паритета по
  ключевым командам (миграция без простоя).

## Объём v0.1 (MVP, вертикальный срез)
1. Домен: `Status`, `Lifecycle`, `Entry`, `Catalog` (инварианты + ошибки).
2. Адаптер: загрузка/сохранение catalog.json.
3. Первый usecase: аудит lifecycle-консистентности (порт `lifecycle_audit.py`).
4. CLI-команда `kbengine audit` поверх него.
Каждый шаг — по TDD, с финальным внешним ревью перед claim.
