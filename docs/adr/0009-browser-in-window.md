# ADR-0009: браузер во вкладке окна DVK

Статус: принято 10.11.2026 (решение владельца: «открывается как финансы, без Docker»).

## Контекст
Нужна вкладка «Браузер», где работают человек и, позже, агент. В окне на Wails v2 один веб-вид: второй браузер внутри не поместить. Wails v3 дает окна, но не веб-виды в одном окне, не возвращает результат JS в Go без обходов (`ExecJS` на внешней странице молча ждет `wails:runtime:ready`), а миграция окна стоит 2-4 дня. У WKWebView нет протокола вроде CDP.

## Решение
Браузер на движке Chromium, который человек уже поставил, запускается отдельным процессом `kbengine browser serve` с отдельным профилем и портом отладки (`--remote-debugging-port=0`). Сервер забирает у него кадры (`Page.startScreencast`), отдает их странице-экрану долгим опросом (`GET /frame?after=N`, не WebSocket: окно v2 не пропускает WebSocket через обработчик ресурсов) и принимает проверенные события (`POST /input`). Окно показывает страницу в iframe через прокси `/browser/` с токеном из `~/.kb-tokens/browser`, как «Финансы» показывают витрину.

## Границы безопасности
- Порт только на loopback; токен в каждом запросе (CDP отдает браузер целиком: входы, cookie).
- События из закрытого списка: мышь с координатами внутри экрана, колесо, текст, имена клавиш, адреса `http(s)`; лишнее поле или неизвестный вид - отказ.
- Окно не передает странице токен и срезает Cookie/Authorization; запись - только JSON с заголовком окна.
- Основной профиль Chrome не трогается: на него порт отладки не вешается.

## Последствия
- Задержка и картинка вместо живой страницы: нет выделения текста мышью, нет курсора на картинке.
- Агент подключается к тому же CDP (отдельный PR): ему нужны свои границы и запрет видеть поля паролей.
- Подстановка из «Доступов» (проверка домена по `Origin` страницы, пароль не попадает в кадры и ответы агенту) - отдельный PR.
- Порт 8790 зашит (`ponytail:`), второй экземпляр невозможен.

## Что проверено
E2E на настоящем Chrome (`KB_BROWSER_E2E=1`): переход, кадр JPEG, клик, кириллица, Backspace, колесо. Холст и WebSocket в WKWebView проверены отдельной пробой; сам iframe в окне DVK - вручную владельцем.
