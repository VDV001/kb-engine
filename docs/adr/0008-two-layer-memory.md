# ADR-0008 — Двухуровневая память из коробки: горячий слой с потолком, холодный с индексом

- Status: proposed (прототип `kbengine memory`, решение владельца о месте — движок)
- Date: 2026-11-09
- Issue: нет (запрос владельца голосом 08.11.2026)

## Context

Владелец просит базу знаний, в которой двухуровневая память есть сразу: человек получает скелет
горячего и холодного слоя, наполняет его руками или поручает агенту, и видно, помогает ли она.

Замер собственной памяти владельца (08.11.2026, нижние оценки):

- горячий слой читается каждым ходом: `CLAUDE.md` 39 796 знаков и индекс `MEMORY.md` 24 691 знак,
  около 20 тыс. токенов на ход (прикидка по знакам, не токенайзером);
- холодный слой: около 210 файлов; за 51 сессию (09.10-06.11) открыто 14 разных, 23 чтения.
  Считались только вызовы `Read`: поиск и `cat` не видны;
- вывод: горячий слой раздулся, холодный почти не открывают, а полезность замеру недоступна —
  виден факт открытия, а не то, помог ли файл.

То есть ценность холодного слоя в том, что он **не загружается**, и в индексе, по которому его
находят. Брать за образец наш раздутый слой нельзя.

## Decision

1. **Раскладка** в папке человека:
   - `HOT.md` — горячий слой, читается в каждой сессии; потолок **4 000 знаков**
     (`--hot-limit` меняет);
   - `cold/INDEX.md` — индекс: одна строка на запись `- [имя](файл.md) — крючок`, крючок до
     **150 знаков**;
   - `cold/<имя>.md` — запись холодного слоя: шапка `name`, `description`, затем текст.
2. **Домен** (`domain.CheckMemory`, `domain.NewColdNote`): знаки считаются знаками, не байтами
   (кириллица); запись без описания, запись без строки в индексе, строка индекса без файла, крючок
   длиннее потолка и горячий слой выше потолка — нарушения с названием класса.
3. **Команды** `kbengine memory init <dir>` (скелет; существующую память не трогает),
   `memory check <dir>` (код 1 и строка на каждое нарушение: пригодно для pre-commit и CI),
   `memory add <dir> --name --description [--body]` (запись и строка индекса вместе: путь агента).
   Человек может править файлы руками; `check` ловит то, что агент или человек положили мимо `add`.
4. **Гейт, а не совет**: потолок горячего слоя проверяется командой. Правило «держи память
   короткой» без исполнителя разошлось бы с практикой, как разошлось у владельца.

## Consequences

- Скелет проходит собственную проверку сразу после `init` (есть тест).
- Агенту дан один способ дописывать холодную память, не раздувая горячую; повышение записи до
  горячей остается решением человека.
- Папку памяти можно подключить источником окна DVK и искать по холодному слою. Это **не
  проверено** в прототипе.

## Ceilings (ponytail)

- Потолок 4 000 знаков выбран как порядок величины, не замером оптимума; путь вверх: потолок в
  токенах модели и замер на реальной памяти нескольких людей.
- Полезность записей не измеряется. Путь вверх: счетчик обращений через MCP (`get_entry`,
  `read_file`) в журнале использования плюс отметка «помогло» человеком; пока статистика
  «открывали N раз» без суждения о пользе.
- Перенос между слоями (повысить в горячий, понизить в холодный) ручной; автоматический
  кандидат по частоте обращений появится только после счетчика.
- `add` пишет запись и строку индекса двумя шагами без транзакции; сбой между ними оставляет
  запись без строки, и `check` назовет ее `not-indexed`.
- Формат шапки читается самодельным разбором двух ключей, не полным YAML.
