# Карта облачного слоя

`map.json` — третья карта репозитория, рядом с картой движка (`docs/architecture-map/`)
и картой рабочего места (в другом дереве). Описывает не то, как движок работает
внутри процесса, а то, как он **доезжает до кластера** и что за ним там смотрит:
манифесты kustomize, чарт Helm, модуль Terraform, метрики и наблюдаемость.

Отдельная карта, а не раздел в карте движка, по механической причине: у движка
описан путь запроса внутри процесса, здесь — путь образа и данных снаружи,
и общих узлов у них ровно два — сам бинарь и его эндпоинты.

## Как смотреть

```sh
kbengine serve --catalog <каталог> --maps docs/architecture-map-cloud/map.json
```

Вкладка `Architecture` рисует карту сама, своей вёрстки у карты нет — только данные.
Флаг повторяемый, карт можно передать несколько.

## Как проверить

```sh
python3 ../architecture-map/validate.py map.json ../..              # проверка
python3 ../architecture-map/validate.py map.json ../.. --self-test  # отрицательный контроль
```

Валидатор один на все карты. Он открывает файл на указанной строке и ищет там
заявленный вызов — по границе слова и вне комментариев. Одиннадцать правил, из них
самые дорогие: источник не может быть тестовым файлом, цепочка шагов не рвётся,
узел не висит вне сценариев, а `unverified` обязан нести причину.

`--self-test` подсаживает тринадцать враний и требует, чтобы каждое было поймано:
проверка, которая никогда не краснела, от сломанной снаружи неотличима.

## Чего карта не может

Подтверждает, что символ стоит рядом с указанной строкой боевого файла, но **не**
что этот вызов участвует именно в описанном потоке. И устаревает молча: приёмка
смысла по зонам здесь ещё не проводилась ни по одной из пяти.

Правишь `deploy/**` — правь карту тогда же. Через месяц будет уже не вспомнить,
а валидатор промолчит: якорь останется целым, соврёт только смысл.
